Algorithm

Adaptive Strategy

Priority-weighted scheduling with dynamic reallocation thresholds.

👑

Priority Scheduling

Processes assigned priority levels (High/Medium/Low). The scheduler grants CPU time proportionally based on weight.

High priority → 1.0× base allocation
Medium priority → 0.65× base allocation
Low priority → 0.3× allocation
🧠

Dynamic CPU Reallocation

When CPU usage exceeds 80%, the allocator throttles low-priority processes to protect critical workloads.

CPU < 80%: Full proportional allocation
CPU ≥ 80%: Low-priority throttled to 50%
CPU ≥ 95%: Critical — Low dropped to 20%
🗜️

Memory Redistribution

Memory exceeding 75% of capacity triggers compaction. Stale low-priority processes are compressed.

Memory < 75%: Demand-based allocation
Memory ≥ 75%: Low-priority trimmed by 30%
Memory ≥ 90%: Force-compact low-priority
⏱️

Starvation Prevention

Processes waiting beyond a threshold gain a priority boost, ensuring no task is indefinitely deprived.

Wait > 10 ticks → Allocation boosted by 25%
Wait > 20 ticks → Flagged as STARVING
Wait > 30 ticks → Forced promotion to HIGH
